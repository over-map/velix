# Region pack pipeline

Builds the Velix offline region packs from open data: every region of the EU, EFTA and the UK (M11), listed in the generated catalogue `regions/europe.json`. It runs in Docker, so local and CI builds match.

```bash
make -C pipeline pack REGION=piemonte   # every stage: extract → elevation → prepare → tiles → hazards → routes → transit → package → validate → smoke
make -C pipeline hazards         # one stage at a time (stages read the previous stages' outputs in pipeline/out/<region>/)
make -C pipeline clean           # remove pipeline/out/<region>/ (downloads stay in pipeline/cache/)
```

Needs Docker (Colima works: `brew install colima && colima start --cpu 6 --memory 12`) and `python3` on the host for the Makefile. A full build takes about 15 minutes on an M1 Pro, plus downloads (the Geofabrik extracts the region needs, cached in `pipeline/cache/`; Lombardy: ≈ 1.8 GB).

**Regions** come from the catalogue `regions/europe.json`, generated by `stages/regions.py` (GitHub workflow *Region catalogue*, run about quarterly; rules in `regions/rules.yml`): each Geofabrik leaf extract that fits is a region, bigger ones are split into admin areas grouped up to 260 MB of OSM data, tiny ones join a neighbour, and today's five Italian regions are pinned. Each entry lists its **source leaves**, every leaf its border + buffer touches across national borders, which `extract.sh` merges. A region's config is `config/_base.yml`, then its catalogue entry, then `config/<region>.yml` when one exists (Italy: timetables, smoke checks, the border by OSM relation). Smoke trips are `config/smoke_trips/<region>.txt` (`id|from|to|min km|max km`), else a generic trip between the region's two largest places (`stages/smoke_trips.py`). Each pack's routing data (tiles, hazards, cycle routes, timetable) covers its region **plus `coverage.buffer_km`** (10 km) past the border (`coverage.geojson`), so a trip just across a border plans in either pack (Valhalla tiles from two builds can't be joined on the phone); the map tiles (basemap, overlays) stop at the border (`map.osm.pbf`).

## Output: `pipeline/out/<region>/pack/`

These files are the GitHub Release assets. The app downloads them one by one and checks each one (`App/Data/RegionPackInstaller.swift`).

| Asset | Content |
|---|---|
| `manifest.json` | version, bbox, the border and the coverage (border + buffer) as simplified polygons, Valhalla version, sizes and sha256 per file (packed and unpacked), sources and licences. Schema: `schema/manifest.schema.json` |
| `valhalla_tiles.tar.xz` | Valhalla 3.9.0 routing tiles. Grades come from GEDTM30; cobbles are a bad surface for routing; the country and region come from the admin build |
| `hazards.sqlite.xz` | `hazards` table + `hazards_rtree`: tram, along, cobbles, steps, gap, dismount, lane (with heading), door; `ways` table: lighting and paths per way id (schema 2, see `stages/hazards.py`) |
| `routes.sqlite.xz` | OSM cycle-route relations (`route=bicycle|mtb`), merged geometry as polyline6, EuroVelo number; schema 2: S7 mix shares (car-free / quiet / unpaved), climb both ways, description, from, to |
| `transit.sqlite.xz` | rail and metro for 60 days from Italy's National Access Point (NeTEx → GTFS, `stages/netex.py`): Trenitalia everywhere, plus each region's own operators (Trenord, ATM, GTT…), `bike_rules` from `config/bikes_allowed_rules.yml`, and `hops`: the OSM track between consecutive stops (`stages/transit_paths.py`; GTFS has no shapes) |
| `city.geojson.xz` | The city area (`region.city_area_relation`, Comune di Milano; else the region's main city by population, `stages/main_city.py`): the app suggests bike + transit when the destination is outside it |
| `basemap.pmtiles.xz` | OpenMapTiles-schema vector tiles z0–14 for the map (planetiler), tiles uncompressed inside the PMTiles so xz compresses across them |
| `overlays.pmtiles.xz` | Velix overlay tiles: `velix_cycling`, `velix_routes`, `velix_transit`, `velix_stations` (see `stages/overlays.py`) |

The budget is **320 MB to download** per region (Filippo: 300 on 16 Oct 2026, 320 with the routing buffer on 2 Nov); `validate` fails the build above it.

## Stages (`stages/`)

| Stage | Image | What it does |
|---|---|---|
| `extract.sh` | tools | The region's Geofabrik leaves (the run's slices, else downloaded md5-checked; merged) → region polygon (`region.osm_relation`, else the catalogue's) → coverage (`coverage.py`: border + buffer, in the region's UTM zone) → `region.osm.pbf`. Also `city.geojson` and `country.osm.pbf` (`country_admin.py`: each country's share of the coverage, from `regions/countries.geojson`, with its OSM name and ISO code) |
| `elevation.py` | tools | GEDTM30 terrain model (COG over HTTP, CC BY 4.0) → 1″ SRTM `.hgt`, used only at build time |
| `prepare_routing.py` | tools | Routing copy of the extract: cobbled ways retagged `surface=dirt` so Valhalla's bicycle costing can avoid them |
| `tiles.sh` | Valhalla 3.9.0 | admins, timezones, tiles with elevation, tar extract |
| `hazards.py` | tools | pyosmium + shapely, two passes over the extract |
| `routes.py` | tools | cycle-route relations |
| `transit.py` + `netex.py` | tools | NAP NeTEx download (the dataset's asset by name) and conversion to GTFS, keeping the feed's `modes` and `lines`; filter, 60-day window. A feed that ends inside the window repeats its last week (`projected`) |
| basemap (Makefile) + `basemap_meta.py` | planetiler 0.10.2 + tools | OpenMapTiles profile on the extract; downloads water polygons, Natural Earth and lake centerlines into `cache/planetiler`; records sources and per-layer sizes |
| `overlays.py` | tools | pyosmium (cycle tags shared with `hazards.py`, route relations) + `metro_colors.py` (P3 families) → tippecanoe → PMTiles |
| `package.py` | tools | xz -9 (single-threaded: identical output on any machine) + manifest |
| `validate.py` | tools | JSON Schema, sizes, sha256, budget |
| `smoke_routes.sh` + `smoke.py` | Valhalla + tools | per region: the trips in `config/smoke_trips/`, the config's `smoke:` expectations (hazard counts and spot checks, EuroVelo, trains, metro stops, city area) |

The pack is a pure function of its inputs: there are no wall-clock timestamps; the build date and transit window start come from the OSM extract date. Rebuilding from the same inputs gives byte-identical SQLite files. The Valhalla tiles match apart from Valhalla's own build stamps (a few bytes per tile), with the same size and the same routes (checked in M2).

## Publishing

`.github/workflows/region-pack.yml` runs monthly (1st, 03:00 UTC), on manual dispatch (`regions`: `all`, `sample` or ids separated by commas; `publish`), and on PRs that touch `pipeline/` (a sample of three: Lombardy, Luxembourg, Paris and around; never signed or published). Jobs (M11 PR 3):

| Job | Runs | What |
|---|---|---|
| `plan` | 1 | `stages/plan_run.py`: the regions and the Geofabrik leaves they need, grouped by country folder |
| `test` | 1 | pipeline unit tests |
| `slice` | one per country (≤ 43) | `make slice`: each leaf downloaded **once** (`stages/fetch_leaf.sh`), cut for every region of the run that needs it (`stages/slice.py`: border + buffer + 5 km), one artifact per region (`slice__<region>__<group>`, kept a day) |
| `build` | one per region (≤ 256) | the region's slices → `slices/<region>/`, which `extract.sh` merges instead of downloading; then `make pack` |
| `golden` | 1 | golden route tests on Lombardy, when the run builds it |
| `sign` | 1 | **environment `pack-publish`**: Filippo approves each run; the only job with `PACK_SIGNING_KEY`. Release tags (`stages/releases.py tags`, from the paginated release list), the new `packs.json` (`stages/index.py`, schema 2: regions not rebuilt keep their previous entry) and Ed25519 signatures of every manifest and the index (`stages/sign.sh`, checked against `keys/pack-signing.pub`) |
| `publish` | one per region | one Release per region, `pack-<region>-YYYY.MM` (`.N` if that tag exists), with `manifest.json.sig` and the notes from `stages/release_notes.py`; a re-run finishes the uploads |
| `index` | 1 | uploads `packs.json` + `packs.json.sig` to the Release `pack-index` once every release it points to exists (else last month's index stays), then deletes `pack-*` releases older than two months that it doesn't point to |

A region whose build fails keeps its previous pack in the index. The app installs only signed manifests and reads only a signed index (`keys/README.md`). Assets are fetched from the index's `mirrors` in order (GitHub today). Locally, `make slice LEAVES="luxembourg saarland" REGIONS=luxembourg` writes the same slices; without them `extract.sh` downloads the leaves itself. Pack binaries never go in git.

## Curated data

Bikes on board follow one order of evidence in every region:
1. the feed's own `trips.txt` `bikes_allowed` flag (`trips.bikes_allowed`);
2. the region's curated rules (`config/bikes_allowed_rules.yml`, one file for every region: by feed and route, each with its source);
3. otherwise `check`.

**Review the rules when an operator changes them.** Trenord marks bikes per train only in its own app, so Trenord trains carry `status: check`. A new region needs curated rules only for feeds without `bikes_allowed`.

The M1 spike tooling stays in `spike/` for reference.
